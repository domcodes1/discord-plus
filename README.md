# Discord Plus

A Tampermonkey userscript for Discord web.

## v3.0.5 fixes (Nov 21, 2026, local only, not yet pushed)

- **Background image, visibility (the fetch worked, the image was hidden):** v3.0.4 proved the GM_xhr fetch works and appMount's background IS the data URL, but the image still never showed — Discord's inner layers paint solid dark backgrounds over appMount. Prime suspect was the variable overrides: v3.0.3/v3.0.4 overrode Discord's background CSS variables on `:root` only, but Discord defines its theme variables on `.theme-dark` / `.theme-light` elements, which override `:root`. The transparent variable overrides now apply to `:root` AND `[class*="theme-dark"]` / `[class*="theme-light"]` / `[class*="theme-"]`, with `!important`, and cover Discord's newer variable names too (`--bg-base-primary`, `--bg-base-secondary`, `--bg-base-tertiary`, `--background-base-low`, `--background-base-lowest`, `--bg-surface-overlay`, plus the older `--background-*` names). Explicit `background-color: transparent !important` rules were added for more current containers (`[class*="content_"]`, `[class*="chatContent_"]`, `[class*="base_"]`, `[class*="layer_"]`), the messages scroller only (`[class*="messagesWrapper_"] [class*="scroller_"]`, not every scroller), and `background-image: none` for the main structural layers. Popouts, modals, tooltips, inputs, message hover states, and the DP panel itself are left alone (only the layer wrapper's background-color is cleared; popout surfaces paint their own). The Midnight preset's solid `:root` background colors no longer apply when a bgUrl is set. Transparency still only applies when a bgUrl is set; Clean stays solid dark with no bgUrl. The "Test background" output now also reports the computed backgroundColor of the main chat container and of the topmost element at viewport center (`document.elementFromPoint`), so the next live test can name the exact layer that is still opaque.
- **Stores, manual factory invocation:** the v3.0.4 probe proved the voice factory (id 903137) is found in req.m but `req(id)` on it THROWS, so the store can never be instantiated that way. `findStore()` now falls back, when `req(id)` throws, to invoking the factory manually with a fake module object (`factory(fakeMod, fakeMod.exports, req)`) and runs the same `expandedCandidates` matching against `fakeMod.exports`. The outcome is recorded in the probe: `manualAttempt` (`ok` / `threw` / `skipped`) and `manualThrewReason` (first 80 chars of the error), surfaced in the Diagnostics line after the existing probe suffix. Everything stays try/catch guarded; a throwing factory can never break the panel.
- **Background test output truncation:** v3.0.4 dumped the entire ~3.2M-char data URL into the panel. `testBackground()` now never prints a full data URL: at most the first 120 chars, followed by its total length. The output still has, in short lines: appMount found/class, appMount computed backgroundImage (truncated) and backgroundColor, body computed backgroundImage (truncated) and backgroundColor, chat bg, center element bg, the plain Image() load result, and the GM_xhr result (status, blob size, data URL length, cached vs session-only, data-URL Image() result). The Test background button now also forces a fresh GM_xhr fetch (clears the once-per-session guard) and a successful test fetch refreshes the stored data URL and re-applies the theme.
- **Background image compression (optional, done):** after the GM_xhr blob loads, the image is drawn to a canvas (max width 1920) and re-encoded as JPEG quality 0.8, and the compressed data URL is used if it is shorter than the raw one. All wrapped in try/catch with an 8s timeout, falling back to the raw blob data URL on any failure. If the compressed URL fits under 2,000,000 chars it is cached in GM storage as before; otherwise session-only. The test output reports whether compression was used.

## v3.0.4 fixes (Nov 21, 2026, local only, not yet pushed)

- **Background image, GM_xmlhttpRequest data URL:** v3.0.3 proved the CSS is correct (appMount bg is set to the tiger URL, transparent) but a plain Image() / CSS url() load of an external image FAILS in Discord (onerror for both the tiger URL and picsum). The script now fetches the background with `GM_xmlhttpRequest` (new `@grant GM_xmlhttpRequest` and `@connect *`), converts the blob to a data URL with FileReader, and uses that as the background. Data URLs under 2,000,000 chars are cached in GM storage (`dp_bg_dataurl_v1` + source URL); larger ones are kept in memory for the session only. The fetch runs in the background on theme apply and never blocks the panel; the raw URL stays as fallback until the fetch lands. The "Test background" button now also reports the GM_xhr result (status, blob size, data URL length, cached vs session-only) and whether an Image() with the data URL loads.
- **Live Now, cumulative cache:** `scanLive()` used to replace the whole live list every 2s, so channels scrolled out of view vanished (SaintLmr was missed entirely on Nov 21). It now merges: channels seen in a scan replace their own user list, channels not seen are kept for up to 60s, then pruned. Stale users live at most 60s.
- **Live Now, wider LIVE / speaking detection:** `streamFromDOM()` / `speakingFromDOM()` only looked inside each voiceUser row, but the LIVE pill sits outside the row. New `liveRowScope()` checks the row's siblings and its wrapper ancestors too, with a trust rule so another user's LIVE pill can never leak in: a wrapper is only trusted when it holds exactly this one voiceUser row, and a sibling only when it holds no voiceUser row at all. Row-level checks kept as before.
- **Store discovery, deeper candidates + probe:** `findStore()` now also checks `exp.default.Z`, `exp.Z.default`, `exp.prototype`, and one level of nested object/function values of exp / exp.default / exp.Z (max 25 keys each, try/catch guarded) in both the req.c and req.m loops, existing candidates first. A `storeProbe` object records what the req.m voice factory search found (factory id, result type, first 12 result keys, nested match, threw) and the Diagnostics line appends ` / probe <factoryId or none> <type> keys:<list or none> nested:<yes|no>`.

## v3.0 features

1. **Live Now** — see who is in voice, who is actually speaking, and who is streaming, without joining the call. Pick a server under Watch server and the Live tab follows it even while you are in DMs or another server. Streaming users get a LIVE badge and a Watch button, which opens Discord's own Watch Stream view.
2. **Deleted messages** — messages you already saw while the tab was open are cached, and when one is deleted it shows up in the Deleted tab with author, time, channel, and content, plus a ghost copy in chat when possible. Only messages seen while Discord was open can be recovered. Messages deleted before you opened the channel, or while Discord was closed, cannot be recovered.
3. **Voice join/leave log** — open the DP button bottom-right, choose a server under Watch server, and the log records who joined or left voice, and when. It reads Discord's own voice data, so it keeps tracking that server even while you are looking at another server or your DMs. If Discord's internal data is not available, it falls back to logging the server you are viewing.
4. **Cleaner look** — the panel is now tabbed (Live / Voice log / Deleted / Look), slimmer, and uses solid Discord-dark colors by default. New default preset is Clean, with Neon, Glass, and Midnight still available, plus an accent color picker and custom background image URL. It also hides the Nitro gift button and the Shop tab.

## Install

1. Install Tampermonkey from the Chrome Web Store.
2. Open the raw script link: https://raw.githubusercontent.com/domcodes1/discord-plus/main/discord-plus.user.js
3. Tampermonkey will offer to install it. Click **Install**.
4. Reload Discord. A DP button appears bottom-right.

Tampermonkey checks the GitHub link for updates automatically, so fixes land without reinstalling. To force an update, open Tampermonkey's dashboard, find Discord Plus, and click **Check for userscript updates**.

## Notes

- The voice log and Live Now only record while the Discord tab is open. They cannot see activity from when Discord was closed.
- Deleted messages only work for messages Discord already showed you while the script was running.
- Background tracking of a chosen server reads Discord's internal voice state data. Discord changes its internals often, so if that breaks, the log falls back to the server you are viewing and the panel says so.
- All settings live in the DP panel (bottom-right button) and in Tampermonkey's menu commands.
